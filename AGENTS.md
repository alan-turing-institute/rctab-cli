# AGENTS.md

Guidance for AI coding agents working in this repository.
Human-facing documentation lives in `docs/` — the detail behind most of this file is in
[`docs/content/development.md`](docs/content/development.md), which is the place to look
(and to update) when something here needs more explanation.

## What this is

`rctab-cli` is the command line interface for **RCTab**, an open-source system for managing
Azure subscriptions and spending. This repository is one component of a larger project
(full docs: <https://rctab.readthedocs.io/en/latest/>). The others are the **RCTab API**
web server, three **function apps** (usage, status, controller), the **fastapimsal**
authentication library, and the Pulumi **infrastructure**.

The CLI has no storage of its own. Every command is an authenticated HTTP request to an
RCTab API server. If a task appears to need a new or changed endpoint, that work belongs in
the RCTab API repository, not here — say so rather than working around it.

## ⚠️ This CLI talks to live systems

`BASE_URL` and `PORT` in the local `.env` decide which server you hit. It may be:

- the **production** RCTab API on Azure,
- a **dev deployment** on Azure, or
- a **local** API server (typically `http://localhost:8000`).

**A developer's `.env` very often points at production**, sometimes with dev URLs commented
out just above it. So:

- **Read `.env` before running any `rctab` command**, and tell the user which server it
  resolves to.
- **Do not run state-changing commands without explicit confirmation for that specific
  run.** These write to the RCTab database: `sub add`, `approve`, `allocate`,
  `set-persistence`, `finance create/update/delete`, `cost-recovery`. `cost-recovery` is
  meant to be run exactly once per month, in order — an accidental production run is not
  easily undone.
- Read-only commands (`summary`, `approvals`, `allocations`, `finance list`, `finance get`)
  are fine to run, but their output contains real subscription IDs, finance codes and
  amounts. Treat it as sensitive and don't paste it into files that might be committed.
- Prefer tests over live calls when verifying a change. `rctab --verbose` echoes the URL
  before calling it.

## Layout

```text
rctab_cli/
├── cli.py          # Typer app, top-level commands, MSAL token acquisition
├── auth.py         # token cache + bearer auth
├── config.py       # CLIConfig (.env) and AuthSettings (.auth.env), pydantic-settings BaseSettings
├── state.py        # global `state`: access token + verbosity
├── types.py        # URL validation types
├── utils.py        # create_url() and helpers
└── sub_apps/sub.py # `rctab sub ...` and `rctab sub finance ...` commands
tests/              # mirrors the package layout
docs/               # Sphinx docs; narrative pages are Markdown in docs/content/
```

Docs: `docs/index.rst` is the entry point and `docs/content/*` is globbed into the toctree,
so a new Markdown page there needs no toctree edit. API reference is generated by
`autosummary` from Google-style docstrings, so a documented function needs a docstring, not
a docs edit. Published at <https://rctab-cli.readthedocs.io/>.

New commands go in `rctab_cli/sub_apps/sub.py` under `@subscription_app.command()` or
`@finance_app.command()`, with a test alongside.

## Testing

**pytest**, in `tests/`. Run with `pytest tests/`. Tests must never hit the network.

Two patterns, often combined in one test:

1. Call the command function **directly** and patch its collaborators with
   `unittest.mock.patch`, naming them **where they are used**
   (`"rctab_cli.sub_apps.sub.add_subscription"`), then assert with `assert_called_once_with`.
2. Invoke through Typer's **`CliRunner`** when argument parsing, option names, defaults or
   prompts matter — default parameter values can only be exercised this way.

Raise `tests.utils.ExitCodeException(result)` instead of asserting on `result.exit_code`;
it surfaces the stdout that `CliRunner` otherwise swallows. Pass `-y` to skip confirmation
prompts.

## Code quality

Run `pre-commit run --all-files`. The hooks (also enforced in CI) are black, isort, mypy,
pylint (`.python-lint`), pydocstyle (Google convention, excluding `tests/`) and
gitleaks. `safety` runs separately via `.pre-commit-safety.yaml`.

Everything in `rctab_cli/` is fully type-annotated and has Google-style docstrings — match
that. Settings use **pydantic v2** with `BaseSettings` from `pydantic-settings`.

CI runs `pytest` against every supported Python version (a matrix in
`.github/workflows/pytest.yml`). Lint and safety run once, on the minimum supported
version, and mypy (`mypy.ini`) and pylint (`.python-lint`) target that minimum explicitly.
When changing `requires-python` in `pyproject.toml`, update all of these, the classifiers
and `.readthedocs.yaml` to match.

## Never commit

- `.env`, `.auth.env`, or any other credentials, tokens or connection strings. Both files
  are git-ignored already.
- **Command output containing real data** — saved `summary`, `finance list` or
  `cost-recovery` responses hold live subscription IDs, finance codes and spend figures.
  Write them outside the repository or to a git-ignored path, and redact before using one
  as a docs example.
- Local cruft: `.venv/`, `.idea/`, `.DS_Store`, `__pycache__/`, `.mypy_cache/`,
  `.pytest_cache/`.

## Keeping this file current

**This file is expected to be maintained.** When you change something it describes —
repository layout, testing approach, tooling, the set of state-changing commands, how
configuration is loaded — update `AGENTS.md` in the same change. If the new information is
useful to humans too, put it in `docs/content/development.md` and keep the summary here
short and pointed at it.

If something in this file turns out to be wrong or out of date, fix it rather than working
around it, and mention the correction to the user.
